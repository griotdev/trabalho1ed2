Este documento consolida as exigências técnicas, normas de compilação e diretrizes de execução estabelecidas pelo Professor Evandro Baccarin para o projeto de Estrutura de Dados II.1. Ambiente e Padrões de DesenvolvimentoSistema Operacional: A correção e a execução automática dos trabalhos serão realizadas exclusivamente em ambiente Linux.  Compilador: É obrigatório o uso do GCC.  Versão da Linguagem: O código deve seguir estritamente o padrão C99.  Segurança: É exigido o uso da flag -fstack-protector-all para proteção contra estouro de pilha.  2. Automação com MakefileO uso do GNU Make é mandatório para coordenar a construção e os testes. O arquivo makefile deve estar na raiz do projeto e conter os seguintes alvos (targets):  TargetFunçãoGeração de ObjetosAlvos individuais para compilar cada módulo do sistema (.o).  tedGera o executável principal chamado ted dentro do diretório /src.  Testes UnitáriosAlvos específicos para compilar e rodar os testes de cada módulo individualmente.  tstallAlvo que compila e executa todos os testes unitários do projeto de uma vez.  Nota: Recomenda-se incluir no makefile as flags -ggdb (depuração), -O0 (sem otimizações) e -Werror=implicit-function-declaration.  3. Organização de DiretóriosO repositório GIT (público) deve seguir a estrutura rigorosa abaixo; arquivos fora do padrão serão apagados antes da correção:  / (Raiz): Contém o makefile e o arquivo LEIA-ME.txt (com matrícula e nome completo).  /src: Abriga os arquivos de implementação (.c) e o executável final ted.  /include: Reservado para os arquivos de cabeçalho (.h).  /tst (ou /test): Contém os arquivos de testes unitários para cada módulo (ex: t_modulo.c).  /unity: Diretório para os arquivos do framework Unity (unity.c, unity.h, etc.).  4. Parâmetros de Linha de Comando (CLI)O programa funciona via interface Bash e deve aceitar os seguintes argumentos em qualquer ordem:  -e path: (Opcional) Diretório-base de entrada ($DIR_ENTRADA).  -f arq.geo: (Obrigatório) Arquivo de descrição da cidade.  -pm arq.pm: (Opcional) Arquivo de pessoas e moradores.  -q arq.qry: (Opcional) Arquivo de consultas e alterações.  -o path: (Obrigatório) Diretório-base de saída para todos os arquivos gerados (.svg, .txt, .hf, .hfd).  5. Critérios Críticos de AvaliaçãoPonteiros Opacos: É proibido definir o corpo de structs nos arquivos .h. O descumprimento acarreta desconto de 2.5 pontos.  Testes Unitários: É obrigatório o uso do framework Unity para validar cada módulo individualmente.  Qualidade de Código: O foco da nota reside na modularização bem-feita e no uso correto das estruturas de dados.  Erro de Compilação: Se o programa não compilar ou não gerar o executável ted, a nota será Zero.  Valgrind: É fortemente recomendado testar o programa com o Valgrind para evitar vazamentos de memória.
